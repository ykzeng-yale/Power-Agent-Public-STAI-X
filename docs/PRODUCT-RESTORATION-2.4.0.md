# Runtime 2.4.0 and product-restoration boundary

The source release combines Sonnet 5.5 scientific roles with counted Haiku 5.5 advisory routing. The hosted web UI always requests the real multi workflow; API/CLI single remains available for research. Actual requested/executed model IDs, code/output, review order, source scope and limits remain recorded. Unequal hosted single/multi capacities are product settings, not a matched comparison.

The eight-file standalone runtime is mirrored exactly in the optional skill runner. Its launcher uses Node built-ins and installed R/jsonlite; it does not require Supabase, Google Cloud or an npm runtime dependency. The optional API adapter and parser/report/document tests need pinned development dependencies and are not started by the default CLI.

The product preserves templates, Files/History/Library and original upload previews, and presents real study specifications, process events, R code, stdout/stderr, result tables, blind review, sources, reports and artifacts. HTML/Markdown previews use sandboxed frames. ZIP exports the actual captured file bytes. Generated sources are explicitly selected for a subsequent analysis with exact bytes, SHA and producer lineage. Browser guest history uses bounded native IndexedDB; storage exhaustion rejects a new write visibly without erasing older history. The local workspace view does not sign out or change a stored owner account.

R execution remains fresh. Bounded RDS/RData artifacts allow explicit saved-state continuation through a new read, not implicit notebook variable persistence. The Aug5 public presentation artifact had no bound executable notebook interface; current capability is reported concretely rather than inferred from historical class names.

Input-parser previews/inspection, executed scientific artifacts, reports compiled from an accepted record and proposed document revisions have distinct provenance. PDF/DOCX revision proposals retain original-source SHA and model/application receipts under a separate bounded budget. They do not overwrite originals or provide independent numerical evidence. Retrieval excerpts/extracted text are not guaranteed complete documents. Conservative literal-result/reference checks do not certify arbitrary mathematical or source interpretation correctness.

Native instructions, mathematical/report checkers and prior native2.3.1 evidence remain unchanged. Runtime2.4.0 engineering regressions and actual production/browser receipts are separate evidence. The2.2.0 scored cohort, original2.3.1 UI failures/qualifications and all historical packages remain retained. No unseen-task accuracy or universal multi-agent superiority claim is made. Source tests alone do not establish deployment or a real browser observation.
