# Reproducible execution record

The bundled runner accepts JSON with `query`, `workflowMode` (`single` or `multi`), optional `context` and `conversationHistory`. It supports bounded `maxModelCalls`, `maxExecutions`, `maxRepairs`, and `deadlineMs`. Do not place expected answers or benchmark oracle metadata in the request.

A result records `scientificStatus`, `success`, `model`, `harnessVersion`, `runId`, `plan`, `answer`, `results`, `design`, `review`, `executions`, `trace`, `usage`, `elapsed_ms`, `fullCode`, and `executionOutput`. The design includes procedure, sidedness, alpha, allocation and sample-size units. Each quantitative result has `metric`, a numeric `value`, and `unit`.

Each executed R script emits a single-line `POWER_AGENT_RESULT=` JSON object containing computed `results: [{metric,value,unit}]`. Simulation output additionally contains `simulation: {seed,trials,failures,mcse,confidence_interval}`. Build this object from computed variables with `jsonlite::toJSON(...,auto_unbox=TRUE,digits=15)`; do not paste a claimed answer as a literal. Returned evidence includes a unique id, role, script, actual stdout/stderr, exit code, elapsed time and SHA256 of the code. The script appends `sessionInfo()` to the output.

For native equal-allocation sample-size records, `design` additionally records `arms`, `allocation_ratio`, and `cluster_size` when clustered. Include all intermediate and final sample-size quantities in `results`; use the same metric for a stage's per-arm and total representations. For example, `sample_size_unrounded` can have both `participants_per_arm` and `participants_total`, while the final `sample_size` can additionally have `clusters_per_arm` and `clusters_total`. Never label per-arm quantities as totals. Preserve distinct names for unrounded versus rounded stages and avoid dead, incorrect calculation functions in delivered code. `check-sample-size-units.py` requires paired count units and verifies equal-arm multiplication, plus participant/cluster arithmetic where both are supplied. It does not infer clinical input validity, check the power formula, or support unequal allocation; those require an independent scientific calculation and an explicit appropriate unit audit. Its input values must come from actual computation, not be replaced to pass the check.

The final answer cites successful coder `evidence_ids`. Its quantitative values and units must agree with structured computed output. A multi-agent numerical pass must cite successful separately executed reviewer evidence. `submit_review` records checks, issues and a pass/revise/needs-clarification verdict. A review is evidence of critique, not a ground-truth label.

For an execution performed through a native host-agent tool, preserve an equivalent record and the actual tool logs. When a requested multi-agent workflow cannot be executed, retain `requested_workflow_mode: "multi"`, `executed_workflow_mode: "single"`, and `independent_review_status: "unavailable"`; do not treat the requested independent validation as completed. Host-native runs do not automatically become benchmark-equivalent to the pinned API runner: record host model, tool/runtime versions, prompt/skill revision and resource limits separately.

`verify-record.mjs` checks internal evidence consistency and code digests. It cannot prove the statistical method is appropriate or prevent an adversary from fabricating an entire record. Use independent reference calculations and source-audited tasks for scientific evaluation.

Native recognized independent/equal-cluster continuous-mean records must additionally pass the limited mathematical reference checker described in [mean-reference-checks.md](mean-reference-checks.md). Internal total/per-arm arithmetic can be consistent while the two-arm variance formula is wrong. Include the supplied input fields and canonical final metrics required by that checker, and retain any failed attempt. Recheck the final record after all changes; store a digest of that exact record with the logs. Host-native prompt instructions do not enforce these actions automatically, so inspect actual tools/evidence and retain failures honestly.

Use `render-record.py` after final verification to create `verified-summary.md`; it rejects stale unit-audit digests and failed/mismatched reference results. It renders the recorded numeric values, design, status, modes, assumptions and check statuses without calculating additional quantities. Numeric conclusions in the final response should quote this report. A deterministic reference check is not an independent agent reviewer, and model-authored summaries are not certified automatically. Missing status or assumptions are displayed as not recorded rather than invented.
